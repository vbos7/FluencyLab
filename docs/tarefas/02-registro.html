Tarefa 02 Pessoa A Pendente

Registro de usuário

Esta é a tarefa mais detalhada do guia — porque é a primeira vez que você vai escrever, do zero, todas as peças que vão se repetir em praticamente toda tarefa seguinte: uma rota, um Form Request de validação, e um Controller. Leia com calma, mesmo que pareça muita coisa — as próximas tarefas vão ser bem mais rápidas porque vão repetir esse mesmo padrão.

O que você vai aprender

  • Como validar dados de entrada com um Form Request (em vez de vários if dentro do Controller).
  • Como criar um registro no banco com Eloquent (User::create()).
  • Como gerar um token Sanctum pro usuário recém-criado.
  • Como registrar uma rota POST em routes/api.php.

Por que isso existe (comparando com PHP puro)

Em PHP puro, validar um formulário de cadastro costuma virar uma sequência de if:

if (empty($_POST['email'])) { $erros[] = 'Email obrigatório'; }
if (!filter_var($_POST['email'], FILTER_VALIDATE_EMAIL)) { $erros[] = 'Email inválido'; }
if (strlen($_POST['senha']) < 8) { $erros[] = 'Senha muito curta'; }
// ... e por aí vai, e geralmente tudo isso fica misturado com o resto da lógica

O Laravel separa essa responsabilidade numa classe própria — o Form Request — que só existe pra dizer "quais campos são obrigatórios e com que formato". Isso mantém o Controller limpo (só com a lógica de negócio) e a validação reaproveitável. Se a validação falhar, o Laravel já devolve um erro 422 formatado automaticamente — você nem precisa escrever esse tratamento.

Passo a passo

1

Criar o Form Request

Dentro do container (lembrete: todo comando artisan roda dentro do Docker, não no seu terminal local):

docker compose exec backend php artisan make:request RegisterRequest

Isso cria backend/app/Http/Requests/RegisterRequest.php. Edite assim:

backend/app/Http/Requests/RegisterRequest.php
<?php

namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

class RegisterRequest extends FormRequest
{
    public function authorize(): bool
    {
        // true = qualquer um pode chamar essa rota (faz sentido, é o cadastro!)
        return true;
    }

    public function rules(): array
    {
        return [
            'name' => ['required', 'string', 'max:255'],
            'email' => ['required', 'email', 'unique:users,email'],
            'password' => ['required', 'string', 'min:8', 'confirmed'],
        ];
    }
}

Repare em três coisas:

  • 'unique:users,email' — o Laravel já confere sozinho se esse email não está cadastrado, sem você escrever um SELECT pra checar.
  • 'confirmed' — esse é o equivalente ao "confirme sua senha" do formulário. Ele espera que o request também tenha um campo password_confirmation com o mesmo valor (é assim que o form de registro do frontend já manda os dados).
  • authorize() não tem nada a ver com "o usuário está logado" — é só "essa pessoa tem permissão de fazer essa requisição", e como é um cadastro aberto, a resposta é sempre true.
2

Criar o Controller

docker compose exec backend php artisan make:controller AuthController
backend/app/Http/Controllers/AuthController.php
<?php

namespace App\Http\Controllers;

use App\Http\Requests\RegisterRequest;
use App\Models\User;
use Illuminate\Support\Facades\Hash;

class AuthController extends Controller
{
    public function register(RegisterRequest $request)
    {
        // $request->validated() só devolve os campos que passaram nas regras
        // do Form Request — ou seja, já filtrado e validado.
        $data = $request->validated();

        $user = User::create([
            'name' => $data['name'],
            'email' => $data['email'],
            'password' => Hash::make($data['password']),
        ]);

        // Gera o token (o "crachá") que o frontend vai guardar e mandar
        // em toda requisição seguinte. O nome 'auth-token' é só um rótulo,
        // útil se um dia o usuário tiver vários tokens (ex: um por dispositivo).
        $token = $user->createToken('auth-token')->plainTextToken;

        return response()->json([
            'user' => $user,
            'token' => $token,
        ], 201);
    }
}

Detalhes que valem a pena entender:

  • RegisterRequest $request no parâmetro do método — o Laravel injeta automaticamente o Form Request certo e já roda a validação antes do método começar a executar. Se a validação falhar, seu código nem chega a rodar.
  • Hash::make() é o equivalente ao password_hash() do PHP puro — nunca, nunca salve senha em texto puro.
  • 201 é o código HTTP de "criado com sucesso" (em vez do genérico 200).
3

Registrar a rota

backend/routes/api.php
use App\Http\Controllers\AuthController;

Route::post('/register', [AuthController::class, 'register']);

Sem ->middleware('auth:sanctum') aqui — faz sentido, ninguém tem token ainda antes de se cadastrar.

Como testar

curl -X POST http://localhost:8000/api/register \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "name": "Maria Silva",
    "email": "maria@exemplo.com",
    "password": "senha1234",
    "password_confirmation": "senha1234"
  }'

Resposta esperada (status 201):

{
  "user": { "id": 1, "name": "Maria Silva", "email": "maria@exemplo.com", "role": "student", ... },
  "token": "1|aBcD3fGhIjKlMnOpQrStUvWxYz..."
}
Testando validação Tente mandar a mesma requisição de novo (email repetido), ou sem o campo password_confirmation. Você deve receber um erro 422 com uma mensagem explicando o que está errado — esse formato de erro já vem pronto do Laravel, é o Form Request fazendo seu trabalho.
