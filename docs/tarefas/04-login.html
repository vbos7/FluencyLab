Tarefa 04 Aluno A Pendente

Login com sessão

Mesma estrutura da tarefa 03. O novo aqui é password_verify() e uma dica de segurança importante.

O arquivo

backend/api/auth/login.php
<?php
require_once __DIR__ . '/../cors.php';
require_once __DIR__ . '/../db.php';

if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    json_out(['error' => 'Método não permitido'], 405);
    exit;
}

$body     = json_decode(file_get_contents('php://input'), true);
$email    = trim($body['email']    ?? '');
$password = $body['password']      ?? '';

if (empty($email) || empty($password)) {
    json_out(['errors' => ['Email e senha são obrigatórios']], 422);
    exit;
}

$stmt = $pdo->prepare("SELECT id, name, email, password_hash, role FROM users WHERE email = ?");
$stmt->execute([$email]);
$user = $stmt->fetch();

// password_verify() compara a senha com o hash salvo
if (!$user || !password_verify($password, $user['password_hash'])) {
    json_out(['errors' => ['Credenciais inválidas']], 401);
    exit;
}

$_SESSION['user_id'] = $user['id'];
$_SESSION['role']    = $user['role'];

json_out([
    'success' => true,
    'user' => [
        'id'    => (int)$user['id'],
        'name'  => $user['name'],
        'email' => $user['email'],
        'role'  => $user['role'],
    ],
]);
Por que "Credenciais inválidas" e não "Email não encontrado"?
Se você disser especificamente qual campo está errado, alguém mal-intencionado consegue descobrir quais emails estão cadastrados só tentando fazer login com vários. A mensagem genérica impede isso.

Como testar (salvando o cookie)

# O -c salva o cookie PHPSESSID num arquivo
curl -s -c /tmp/cookies.txt -X POST http://localhost:8000/api/auth/login.php \
  -H "Content-Type: application/json" \
  -d '{"email":"ana@test.com","password":"123456"}'

Guarde o arquivo de cookie (/tmp/cookies.txt) — você vai precisar dele pra testar rotas protegidas nas próximas tarefas com o flag -b /tmp/cookies.txt.
