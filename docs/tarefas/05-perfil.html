Tarefa 05 Pessoa A Pendente

Ver e editar perfil

Duas rotas simples, que reaproveitam tudo que você já viu: uma GET que devolve dados (parecido com a rota /api/user da tarefa 01) e uma PUT que atualiza, reaproveitando o padrão de Form Request + Eloquent da tarefa 02.

O que você vai aprender

  • O verbo HTTP PUT (atualizar um recurso existente) — diferente do POST (criar) que você já usou.
  • Como atualizar um Model existente com Eloquent ($user->update([...])).

Passo a passo

1

Form Request de atualização

docker compose exec backend php artisan make:request UpdateProfileRequest
backend/app/Http/Requests/UpdateProfileRequest.php
public function authorize(): bool
{
    // diferente do registro: aqui SIM importa quem está logado —
    // mas isso já é garantido pelo middleware auth:sanctum na rota,
    // então aqui só liberamos geral.
    return true;
}

public function rules(): array
{
    return [
        'name' => ['sometimes', 'string', 'max:255'],
        'email' => ['sometimes', 'email', 'unique:users,email,' . $this->user()->id],
    ];
}

Duas diferenças importantes em relação ao Form Request da tarefa 02:

  • 'sometimes' em vez de 'required' — o usuário pode mandar só o campo que quer mudar (ex: só o nome), não precisa reenviar tudo.
  • 'unique:users,email,' . $this->user()->id — a regra de "email único" ignora o próprio usuário. Sem isso, ele nunca conseguiria salvar o perfil mantendo o mesmo email (porque o Laravel acharia que já existe um registro com aquele email — o dele mesmo!).
2

Controller

Crie um novo Controller pra isso (faz mais sentido separar de AuthController, já que não é sobre autenticação, é sobre o perfil em si):

docker compose exec backend php artisan make:controller ProfileController
backend/app/Http/Controllers/ProfileController.php
<?php

namespace App\Http\Controllers;

use App\Http\Requests\UpdateProfileRequest;
use Illuminate\Http\Request;

class ProfileController extends Controller
{
    public function show(Request $request)
    {
        return $request->user();
    }

    public function update(UpdateProfileRequest $request)
    {
        $request->user()->update($request->validated());

        return $request->user();
    }
}

$request->user() é o usuário "decifrado" a partir do token — o Sanctum já fez esse trabalho antes do seu método rodar.

3

Registrar as rotas

backend/routes/api.php
use App\Http\Controllers\ProfileController;

Route::middleware('auth:sanctum')->group(function () {
    Route::get('/profile', [ProfileController::class, 'show']);
    Route::put('/profile', [ProfileController::class, 'update']);
});

Route::middleware(...)->group(...) é um jeito de aplicar o mesmo middleware em várias rotas de uma vez, em vez de repetir ->middleware('auth:sanctum') em cada linha.

Como testar

curl -X PUT http://localhost:8000/api/profile \
  -H "Authorization: Bearer SEU_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{"name": "Maria S. Silva"}'
