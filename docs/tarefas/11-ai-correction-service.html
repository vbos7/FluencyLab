Tarefa 11 Pessoa B Pendente

Serviço de correção por IA

Esta tarefa não tem nada de mágico de IA — é, no fundo, fazer uma requisição HTTP pra um serviço externo (a OpenAI) e tratar a resposta, igual você faria com qualquer outra API. A diferença é que, em vez de pedir "me devolva os dados do usuário 5", a gente está pedindo "compare estas duas frases e me diga se a tradução está certa". Não estamos inventando essa lógica do zero — ela já existe, testada, em ~/Developer/english-practice/app/Services/AiCorrectionService.php. Esta tarefa é adaptar esse código pro fluency-lab.

O que você vai aprender

  • O que é uma Service class — uma classe que não é Model nem Controller, só agrupa uma lógica específica (aqui: "conversar com a API da OpenAI").
  • Como fazer uma requisição HTTP de dentro do Laravel (Illuminate\Support\Facades\Http) — o equivalente a um curl ou file_get_contents com contexto, só que com uma API mais confortável.
  • Como montar um "prompt" (a instrução em texto que mandamos pra IA) pedindo uma resposta em formato JSON estruturado.

Por que isso existe

Pensa numa correção de prova: você (professor) olha a resposta do aluno, compara com o gabarito, e escreve um feedback. A IA está fazendo exatamente esse papel aqui — só que em vez de "escrever um feedback" solto, pedimos pra ela devolver isso já organizado em campos (nota, erros encontrados, sugestão de correção), porque é isso que o frontend vai exibir na tela.

Passo a passo

1

Conseguir uma chave de API da OpenAI

Crie uma conta em platform.openai.com e gere uma API key (em "API keys" no painel). O modelo usado aqui (gpt-4o-mini) é o mais barato da OpenAI — dá pra testar bastante sem gastar muito.

Nunca commite a chave Ela vai entrar só no backend/.env (que já está no .gitignore), nunca no .env.example nem em código.
backend/.env
OPENAI_API_KEY=sk-...
backend/.env.example
OPENAI_API_KEY=

Registre a variável em config/services.php (é assim que o Laravel recomenda ler chaves de API — em vez de usar env() espalhado pelo código):

backend/config/services.php
'openai' => [
    'key' => env('OPENAI_API_KEY'),
],
2

Criar a Service class

Diferente de Model/Controller, não existe um comando artisan make:service — é só uma classe PHP normal, num diretório app/Services/ que você mesmo cria.

backend/app/Services/AiCorrectionService.php
<?php

namespace App\Services;

use Illuminate\Support\Facades\Http;
use Illuminate\Support\Facades\Log;

class AiCorrectionService
{
    protected string $apiKey;
    protected string $model;

    public function __construct()
    {
        $this->apiKey = config('services.openai.key');
        $this->model = 'gpt-4o-mini';
    }

    public function correctTranslation(string $pt, string $enReference, string $userAnswer): array
    {
        $prompt = $this->buildPrompt($pt, $enReference, $userAnswer);

        try {
            $response = Http::timeout(30)
                ->withHeaders([
                    'Authorization' => 'Bearer ' . $this->apiKey,
                    'Content-Type' => 'application/json',
                ])
                ->post('https://api.openai.com/v1/chat/completions', [
                    'model' => $this->model,
                    'messages' => [
                        [
                            'role' => 'system',
                            'content' => 'Você é um professor de inglês especializado em correção de traduções. Sempre responda em JSON válido.',
                        ],
                        [
                            'role' => 'user',
                            'content' => $prompt,
                        ],
                    ],
                    'response_format' => ['type' => 'json_object'],
                    'temperature' => 0.3,
                ]);

            if ($response->failed()) {
                Log::error('OpenAI API Error', [
                    'status' => $response->status(),
                    'body' => $response->body(),
                ]);
                throw new \Exception('Erro na API da OpenAI: ' . $response->body());
            }

            $content = $response->json('choices.0.message.content');

            if (! $content) {
                throw new \Exception('Resposta vazia da API.');
            }

            $result = json_decode($content, true);

            if (json_last_error() !== JSON_ERROR_NONE) {
                Log::error('Erro ao decodificar JSON da IA', ['content' => $content]);
                throw new \Exception('Erro ao processar resposta da IA: ' . json_last_error_msg());
            }

            return $result;
        } catch (\Exception $e) {
            Log::error('AiCorrectionService falhou', ['message' => $e->getMessage()]);
            throw $e;
        }
    }

    protected function buildPrompt(string $pt, string $enReference, string $userAnswer): string
    {
        return <<<PROMPT
Você é um professor de inglês especializado em correção de traduções do português para o inglês.

IMPORTANTE:
- Avalie se a tradução está CORRETA, não se está idêntica à referência.
- Contrações (She's, They're, I'm) são equivalentes às formas completas (She is, They are, I am).
- A referência é apenas um EXEMPLO, não a única resposta correta.

Frase original (PT): {$pt}
Tradução de referência (EN): {$enReference}
Tradução do aluno (EN): {$userAnswer}

Retorne APENAS um JSON com esta estrutura, sem texto antes ou depois, sem markdown:
{
  "is_correct": true ou false,
  "score": número de 0 a 100,
  "overall_comment": "comentário geral em português",
  "mistakes": [
    {"type": "grammar", "original": "trecho errado", "suggestion": "correção", "explanation_pt": "explicação em português"}
  ],
  "corrected_sentence": "frase corrigida (ou a frase exata do aluno, se não houver erro)",
  "positive_points": ["o que o aluno acertou"]
}
PROMPT;
    }
}
O que mudou em relação ao english-practice? A lógica é idêntica — só os nomes dos parâmetros (pt/enReference/userAnswer, batendo com as colunas phrases.pt/phrases.en que você criou na tarefa 10) e o prompt foi enxugado um pouco (o original tem mais exemplos dentro do prompt — pode copiar eles do projeto de referência se quiser respostas ainda mais consistentes).
3

Testar isoladamente, sem rota nenhuma

Antes de conectar isso numa rota (vai acontecer na tarefa 12), dá pra testar o Service sozinho com o tinker — um console interativo do Laravel pra rodar código PHP contra a aplicação real:

docker compose exec backend php artisan tinker

Dentro do tinker:

$service = app(\App\Services\AiCorrectionService::class);
$service->correctTranslation(
    'Eu gostaria de um café, por favor.',
    'I would like a coffee, please.',
    'I want a coffee please'
);

Deve devolver um array PHP com is_correct, score, mistakes, etc. Se der erro de autenticação, confira se o OPENAI_API_KEY está certo no .env e se você reiniciou o container depois de editar o .env (docker compose restart backend).

Nota lateral: existe alternativa sem OpenAI?

Sim — o projeto de referência também tem uma versão usando o Gemini (Google), em AiCorrectionServiceGemini.php, caso prefira não usar a OpenAI. A estrutura é a mesma (monta um prompt, faz uma requisição HTTP, parseia o JSON) — só muda a URL da API e o formato exato da resposta. Não é necessário pro fluxo principal, mas fica registrado caso o time decida trocar depois.
