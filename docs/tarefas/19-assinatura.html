Assinar um plano

Não existe gateway de pagamento neste projeto ainda — essa tarefa só registra "esse usuário está no plano X", pra já deixar a estrutura pronta pra integrar um pagamento de verdade no futuro.

O que você vai aprender

  • O que é uma tabela pivot — uma tabela que só existe pra conectar dois outros models (aqui: qual usuário está em qual plano).

Controller

use App\Models\UserPlan;
use App\Models\Plan;
use Illuminate\Http\Request;

public function subscribe(Request $request)
{
    $request->validate([
        'plan_id' => ['required', 'exists:plans,id'],
    ]);

    $plan = Plan::findOrFail($request->plan_id);

    $userPlan = UserPlan::create([
        'user_id' => $request->user()->id,
        'plan_id' => $plan->id,
        'started_at' => now(),
        'expires_at' => $plan->billing_period === 'lifetime' ? null : now()->addMonth(),
        'status' => 'active',
    ]);

    return response()->json($userPlan, 201);
}
$request->validate() direto no método Pra uma validação simples de um campo só, nem sempre vale a pena criar um Form Request separado (como você fez nas tarefas 02, 03 e 12) — dá pra validar direto assim, mais rápido de escrever. Use Form Request quando as regras forem mais complexas ou repetidas em mais de um lugar.
