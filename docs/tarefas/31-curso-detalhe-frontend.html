Tarefa 31 Pessoa B Pendente

Detalhe do curso e aulas

Esta tarefa é um pouco maior que a anterior, porque mexe na estrutura de rotas. Hoje existem três páginas quase idênticas: app/cursos/basico/page.tsx, .../intermediario/page.tsx e .../avancado/page.tsx, cada uma com a lista de aulas escrita à mão. Com a API te dando o curso certo a partir do slug (que já existe desde a tarefa 07 do backend), dá pra unificar essas três páginas numa só.

O que você vai aprender

  • Rotas dinâmicas no Next.js — uma pasta entre colchetes, tipo [slug], vira um "parâmetro" que casa com qualquer URL naquele formato.
  • Como combinar Server Component (busca dado) + Client Component (interatividade), reaproveitando exatamente o padrão que practice-controller.tsx já usa neste projeto — vale dar uma olhada nele antes de começar.

Passo a passo

1

Criar a rota dinâmica

Apague as três pastas antigas (basico/, intermediario/, avancado/) e crie uma nova:

frontend/app/cursos/[slug]/page.tsx
frontend/app/cursos/[slug]/page.tsx
import { fetchFromApi } from "@/app/_lib/server-api"
import { CourseLessons } from "@/app/_components/cursos/course-lessons"

type Lesson = { id: number; title: string; duration: string; youtube_id: string }
type CourseDetail = { id: number; slug: string; title: string; lessons: Lesson[] }

export default async function CursoDetalhePage({
    params,
}: {
    params: Promise<{ slug: string }>
}) {
    const { slug } = await params
    const course = await fetchFromApi<CourseDetail>(`/courses/${slug}`)

    return <CourseLessons course={course} />
}
params é uma Promise? Sim — em versões recentes do Next.js (App Router), os parâmetros de rota dinâmica chegam como uma Promise, por isso o await params. É só uma particularidade da versão do framework, não precisa entender o porquê agora — só lembrar do padrão.
2

Mover a parte interativa pra um Client Component

Tudo que hoje está dentro de BasicoPage (estado de qual aula está tocando, comentários) vira um novo arquivo, recebendo os dados já prontos como prop — exatamente como o PracticeController recebe phrases:

frontend/app/_components/cursos/course-lessons.tsx
"use client"

import { useState } from "react"
// ... resto dos imports que já existiam no arquivo antigo (ícones, NavLayout, etc)

type Lesson = { id: number; title: string; duration: string; youtube_id: string }
type Course = { title: string; lessons: Lesson[] }

export function CourseLessons({ course }: { course: Course }) {
    const [aulaAtiva, setAulaAtiva] = useState(0)
    // ... o resto do estado (drawerAberto, comentarios, novoComentario) continua igual

    const aula = course.lessons[aulaAtiva]

    return (
        // ... o JSX que já existia, só trocando aulas[aulaAtiva].titulo por
        // aula.title, aulas[aulaAtiva].youtubeId por aula.youtube_id, etc.
        // E o .map() de aulas vira course.lessons.map(...)
        <div />
    )
}

O grosso do trabalho aqui é mecânico: pegue o JSX que já existia no arquivo antigo e cole dentro desse novo componente, ajustando os nomes dos campos (titulo → title, youtubeId → youtube_id) e trocando a fonte da lista de aulas (array fixo) para course.lessons (vindo da prop).

3

Atualizar os links da listagem

Confira que os links em cursos/page.tsx (tarefa 30) apontam pra /cursos/${course.slug} — já deveriam estar assim, mas vale conferir, já que agora essa URL precisa bater exatamente com a pasta [slug] nova.

4

Comentários — opcional

Os comentários podem continuar sendo só locais (estado em memória, como já eram) por enquanto. Se a tarefa 09 do backend já estiver pronta, dá pra trocar o enviarComentario() por uma chamada apiClient.post(\`/lessons/${'${aula.id}'}/comments\`, { text: novoComentario }) — mesmo padrão de Client Component chamando API que você já viu nas tarefas 25/26.
