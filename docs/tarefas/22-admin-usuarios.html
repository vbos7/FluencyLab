Tarefa 22 Pessoa A Extra

Gerenciar usuários (admin)

Até agora cada tarefa criou uma rota por vez. Aqui você vai ver o atalho que o Laravel oferece quando precisa de todas as ações de CRUD (listar, ver um, criar, editar, apagar) de uma vez: Route::apiResource.

O que você vai aprender

  • Route::apiResource — registra 5 rotas (index, store, show, update, destroy) numa linha só.
  • Route model binding — como o Laravel já te entrega o Model certo, sem você precisar escrever User::findOrFail($id) na mão.

Passo a passo

1

Controller

docker compose exec backend php artisan make:controller Admin/UserController --api
backend/app/Http/Controllers/Admin/UserController.php
use App\Models\User;
use Illuminate\Http\Request;

class UserController extends Controller
{
    public function index()
    {
        return User::orderByDesc('created_at')->paginate(20);
    }

    public function show(User $user)
    {
        return $user;
    }

    public function update(Request $request, User $user)
    {
        $data = $request->validate([
            'name' => ['sometimes', 'string', 'max:255'],
            'role' => ['sometimes', 'in:admin,student'],
        ]);

        $user->update($data);

        return $user;
    }

    public function destroy(User $user)
    {
        $user->delete();

        return response()->json(null, 204);
    }
}
show(User $user) e update(Request $request, User $user) Repare que você não precisa buscar o usuário manualmente (User::find($id)) — basta tipar o parâmetro como User $user que o Laravel já entende que o {user} da URL é um ID, busca o registro sozinho, e já devolve 404 automaticamente se não existir. Isso se chama route model binding.

paginate(20) em vez de get() — com potencialmente muitos usuários, devolver tudo de uma vez ficaria pesado. paginate já devolve só uma página por vez, com metadados (total de páginas, próxima página, etc) prontos no JSON.

2

Rotas — todas de uma vez

backend/routes/api.php
use App\Http\Controllers\Admin\UserController;

Route::middleware(['auth:sanctum', 'admin'])->group(function () {
    Route::apiResource('admin/users', UserController::class)->except(['store']);
});

Isso registra de uma vez: GET /admin/users, GET /admin/users/{user}, PUT /admin/users/{user} e DELETE /admin/users/{user}. O ->except(['store']) tira a rota de "criar usuário" (não implementamos store no Controller acima — criar usuário direto pelo admin não é um caso de uso essencial agora; se quiser, adicione o método e tire o except).

Como testar

curl http://localhost:8000/api/admin/users \
  -H "Authorization: Bearer TOKEN_DE_UM_ADMIN" \
  -H "Accept: application/json"

Pra esse teste funcionar, o usuário do token precisa ter role = 'admin' no banco — você pode mudar isso direto no tinker: User::find(1)->update(['role' => 'admin']);
