Tarefa 04 Pessoa A Pendente

Logout e "quem sou eu"

O que você vai aprender

  • Como "apagar" um token (logout) — o equivalente a session_destroy().
  • Que a rota GET /api/user (já pronta desde a tarefa 01) é o jeito padrão do frontend perguntar "quem está logado agora?".

Por que isso existe

Sessão tradicional tem session_destroy() pra "esquecer" o usuário. Com token, a lógica é parecida: como não existe estado guardado no servidor pra cada navegador, "deslogar" significa simplesmente apagar o token do banco — depois disso, qualquer requisição que tentar usar aquele token vai ser barrada pelo auth:sanctum, porque ele não existe mais.

Passo a passo

1

Método logout() no AuthController

backend/app/Http/Controllers/AuthController.php
public function logout(Request $request)
{
    // currentAccessToken() pega o token que foi usado NESSA requisição
    // (o Sanctum sabe disso pelo header Authorization) e apaga ele.
    $request->user()->currentAccessToken()->delete();

    return response()->json(['message' => 'Logout realizado com sucesso.']);
}
2

Registrar a rota — repare que esta usa o middleware

backend/routes/api.php
Route::post('/logout', [AuthController::class, 'logout'])->middleware('auth:sanctum');

Diferente de /register e /login, essa rota precisa do middleware — só faz sentido deslogar quem já está logado (o Laravel precisa saber, via o token, qual usuário/token apagar).

Como testar

# 1. Logout (troque SEU_TOKEN pelo token que você recebeu no login)
curl -X POST http://localhost:8000/api/logout \
  -H "Authorization: Bearer SEU_TOKEN" \
  -H "Accept: application/json"

# 2. Tente usar o MESMO token de novo — agora deve dar 401
curl http://localhost:8000/api/user \
  -H "Authorization: Bearer SEU_TOKEN" \
  -H "Accept: application/json"

A rota "quem sou eu" já está pronta

Não precisa criar nada novo aqui — a rota GET /api/user, que já existe desde a tarefa 01, já é exatamente o que o frontend usa pra saber quem está logado a cada vez que a página carrega: ele manda o token guardado e recebe os dados do usuário de volta (ou um 401, se o token não for mais válido).
