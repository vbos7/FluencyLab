Tarefa 33 Pessoa B Pendente

Submeter e exibir a correção por IA

Esta é a tarefa que fecha o ciclo inteiro do projeto: troca a correção fake por Levenshtein pela chamada real pro POST /api/practice/check-answer, que por trás dos panos chama o AiCorrectionService que vocês construíram nas tarefas 11 e 12 do backend.

O que vai mudar

Em practice-controller.tsx, a função handleVerify hoje é síncrona (calcula tudo na hora, sem esperar nada):

const handleVerify = () => {
    if (!answer.trim()) return
    const score = scoreAnswer(answer, phrase.en)
    const fb = generateFeedback(answer, phrase.en, score)
    setFeedback(fb)
    setEarnedXp(fb.xp)
    // ...
}

Vai virar assíncrona (precisa esperar a resposta da IA, que demora 1-3 segundos) e usar dados reais vindos da API em vez de calculados localmente.

O desafio: a IA devolve um formato diferente do que a tela espera

A tela usa um formato de feedback (tipo Feedback, em _lib/practice.ts) com campos como status, title, corrections. Já a resposta da API (que vem do AiCorrectionService, lembra da tarefa 11?) tem campos diferentes: is_correct, score, mistakes, corrected_sentence. Em vez de reescrever toda a tela pra usar os nomes da API, vamos criar uma pequena função "tradutora" — um padrão bem comum, chamado de adapter: pega um formato e devolve outro, sem mexer no resto do código.

Passo a passo

1

Criar a função adaptadora

frontend/app/_components/practice/practice-controller.tsx
import { apiClient } from "@/app/_lib/api"

type AiFeedback = {
    is_correct: boolean
    score: number
    overall_comment: string
    mistakes: { type: string; original: string; suggestion: string; explanation_pt: string }[]
    corrected_sentence: string
    positive_points: string[]
}

function adaptAiFeedback(ai: AiFeedback, xp: number): Feedback {
    const status: Feedback["status"] =
        ai.score >= 95 ? "perfect" : ai.score >= 70 ? "good" : ai.score >= 40 ? "partial" : "needs_work"

    const titles: Record<Feedback["status"], string> = {
        perfect: "Perfeito!",
        good: "Muito bem!",
        partial: "Quase lá!",
        needs_work: "Vamos praticar mais",
    }

    return {
        status,
        title: titles[status],
        message: ai.overall_comment,
        corrections: ai.mistakes.map((m) => ({
            wrong: m.original,
            correct: m.suggestion,
            explanation: m.explanation_pt,
        })),
        xp,
    }
}
Mesmas faixas de score, em dois lugares Repare que essas faixas (≥95, ≥70, ≥40) são as mesmas que você já usou no backend, na função calculateXp() da tarefa 12. Não tem como compartilhar esse código entre backend (PHP) e frontend (TypeScript) diretamente — são linguagens/projetos diferentes — então é normal (e aceitável, pra esse projeto) ter a mesma regrinha escrita duas vezes. Só fique de olho: se um dia mudar uma faixa, lembre de mudar nos dois lugares.
2

Trocar handleVerify por uma versão assíncrona

const [loading, setLoading] = useState(false)

const handleVerify = async () => {
    if (!answer.trim()) return

    setLoading(true)
    try {
        const response = await apiClient.post("/practice/check-answer", {
            phrase_id: phrase.id,
            answer,
        })

        const fb = adaptAiFeedback(response.data.feedback, response.data.xp_earned)
        setFeedback(fb)
        setEarnedXp(fb.xp)
        setShowXpToast(true)
        setTimeout(() => setShowXpToast(false), 2000)

        const parts = [fb.title, fb.message]
        if (fb.corrections.length > 0) {
            parts.push(`Tradução esperada: ${fb.corrections[0].correct}.`)
            parts.push(fb.corrections[0].explanation)
        }
        parts.push(`Você ganhou ${fb.xp} XP.`)
        setSrAnnouncement("")
        setTimeout(() => setSrAnnouncement(parts.join(" ")), 50)
    } catch (err) {
        console.error("Erro ao corrigir resposta:", err)
    } finally {
        setLoading(false)
    }
}

Repare que a estrutura de baixo (anúncio pro leitor de tela, toast de XP) continua igual — só o jeito de conseguir o fb (feedback) mudou, de cálculo local pra chamada de API.

3

Mostrar um estado de carregando

Como a IA demora 1-3 segundos pra responder, é importante o botão de "Verificar" avisar que está processando — senão parece que travou. Encontre o botão que chama handleVerify (provavelmente dentro de answer-form.tsx, que recebe uma prop tipo onVerify) e adicione um disabled={loading} + troque o texto enquanto carrega, igual fez nas tarefas 25 e 26.

4

Limpar o que não é mais usado

Depois de tudo funcionando, pode remover o import de scoreAnswer/generateFeedback do topo do arquivo (a "gambiarra" da apresentação não é mais necessária) — mantenha só type Phrase e type Feedback.

Como testar

Pratique uma frase pela tela de verdade. A resposta deve demorar alguns segundos (é a chamada real pra OpenAI) e mostrar um feedback condizente com o que você escreveu — erre de propósito uma frase pra ver a IA apontando o erro, e acerte outra pra ver o "Perfeito!".
