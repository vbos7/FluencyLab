Tarefa 03 Pessoa A Pendente

Login

A mecânica de Form Request + Controller + Rota já foi explicada por inteiro na tarefa 02 — aqui o foco é só na parte nova: conferir uma senha e devolver um token.

O que você vai aprender

  • Como comparar a senha enviada com o hash salvo no banco (Hash::check).
  • Como buscar um registro por uma coluna específica (User::where(...)->first()).

Por que isso existe (comparando com PHP puro)

No PHP puro, o login costuma ser:

$sql = "SELECT * FROM usuarios WHERE email = '$email'";
$usuario = mysqli_fetch_assoc(mysqli_query($conn, $sql));
if ($usuario && password_verify($senha, $usuario['senha'])) {
    $_SESSION['usuario_id'] = $usuario['id'];
}

A diferença não está na lógica (é a mesma: buscar pelo email, comparar a senha) — está em o que acontece depois de confirmar quem é o usuário. Em vez de $_SESSION[...], geramos um token (ver Fundamentos).

Passo a passo

{
    return true;
}

public function rules(): array
{
    return [
        'email' => ['required', 'email'],
        'password' => ['required', 'string'],

2

Método login() no AuthController

Adicione este método na mesma classe AuthController criada na tarefa anterior:

backend/app/Http/Controllers/AuthController.php
use App\Http\Requests\LoginRequest;
use Illuminate\Validation\ValidationException;

public function login(LoginRequest $request)
{
    $data = $request->validated();

    $user = User::where('email', $data['email'])->first();

    if (! $user || ! Hash::check($data['password'], $user->password)) {
        // ValidationException devolve um 422, no mesmo formato que o
        // Form Request já usa — então o frontend trata os dois casos
        // do mesmo jeito.
        throw ValidationException::withMessages([
            'email' => ['Credenciais inválidas.'],
        ]);
    }

    $token = $user->createToken('auth-token')->plainTextToken;

    return response()->json([
        'user' => $user,
        'token' => $token,
    ]);
}
Por que não dizer qual campo está errado? Repare que a mensagem de erro não diz se foi o email ou a senha que estava errada — só "credenciais inválidas". Isso é proposital: se o erro fosse específico ("esse email não existe"), alguém mal-intencionado poderia descobrir quais emails estão cadastrados só tentando fazer login com vários.
3

Registrar a rota

backend/routes/api.php
Route::post('/login', [AuthController::class, 'login']);

Como testar

curl -X POST http://localhost:8000/api/login \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{"email": "maria@exemplo.com", "password": "senha1234"}'

Deve devolver user + token, igual ao registro. Guarde esse token — você vai usar nele na próxima tarefa.
