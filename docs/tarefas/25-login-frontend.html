Tarefa 25 Pessoa A Pendente

Conectar o login

Hoje o botão "Entrar" em frontend/app/_components/auth/login-form.tsx não faz nenhuma chamada real — ele só navega direto pra /home. Esta tarefa troca isso por uma chamada de verdade pro POST /api/login que você construiu na tarefa 03 do backend.

O que você vai aprender

  • Como chamar a API a partir de um Client Component, usando o apiClient da tarefa 24.
  • Como guardar o token recebido num cookie (js-cookie), pra ele ficar disponível tanto pro apiClient quanto pro fetchFromApi das próximas telas.
  • Como mostrar uma mensagem de erro quando a API recusa o login.

Onde mexer

O LoginForm já é um Client Component ("use client" no topo) com useState pra email e password. O botão "Entrar" hoje é assim:

<button
    onClick={() => {
        localStorage.removeItem("fluency-lab:mode")
        localStorage.setItem("fluency-lab:firstLogin", "true")
        router.push("/home")
    }}
    type="button"
>
    Entrar
</button>

Passo a passo

1

Importar o que vai precisar

frontend/app/_components/auth/login-form.tsx
import { apiClient } from "@/app/_lib/api"
import Cookies from "js-cookie"

Adicione também um estado novo, pra guardar mensagem de erro e o estado de "carregando":

const [error, setError] = useState<string | null>(null)
const [loading, setLoading] = useState(false)
2

Criar a função de login

async function handleLogin() {
    setError(null)
    setLoading(true)

    try {
        const response = await apiClient.post("/login", { email, password })
        const { token } = response.data

        // expires: 7 — o cookie dura 7 dias antes de expirar sozinho
        Cookies.set("token", token, { expires: 7 })

        localStorage.removeItem("fluency-lab:mode")
        localStorage.setItem("fluency-lab:firstLogin", "true")
        router.push("/home")
    } catch (err) {
        setError("Email ou senha incorretos.")
    } finally {
        setLoading(false)
    }
}
try/catch, igual você já conhece Se a API responder com erro (ex: 422, credenciais inválidas — lembra da tarefa 03 do backend?), o axios lança uma exceção automaticamente quando o status não é 2xx, que cai no catch. É o equivalente a checar if ($http_code !== 200) manualmente, só que o axios já faz isso por você.
3

Trocar o botão

<button onClick={handleLogin} type="button" disabled={loading}>
    {loading ? "Entrando..." : "Entrar"}
</button>

{error && (
    <p className="mt-2 text-center text-sm text-red-500">{error}</p>
)}

O disabled={loading} evita que o usuário clique duas vezes enquanto a requisição ainda está em andamento.

Como testar

Com o backend rodando (docker compose up -d) e algum usuário já cadastrado (curl da tarefa 02, ou cadastre um direto pelo formulário depois que a tarefa 26 estiver pronta), tente logar pela tela. Abra o DevTools do navegador → aba Application → Cookies, e confira que um cookie token apareceu depois do login.
