Logout e proteger rotas

Duas coisas nesta tarefa: fazer o botão de logout chamar a API de verdade, e impedir que alguém sem login acesse páginas como /home ou /practice digitando a URL direto.

O que você vai aprender

  • O que é um middleware no Next.js — parecido em espírito com o auth:sanctum do Laravel, mas do lado do frontend.

Parte 1 — Logout

1
frontend/app/_components/profile/logout-button.tsx
"use client"

import { useRouter } from "next/navigation"
import { LogOut } from "lucide-react"
import { apiClient } from "@/app/_lib/api"
import Cookies from "js-cookie"

export function LogoutButton() {
    const router = useRouter()

    async function handleLogout() {
        try {
            await apiClient.post("/logout")
        } catch {
            // mesmo se a chamada falhar (ex: token já tinha expirado),
            // seguimos limpando o cookie local — não faz sentido travar
            // o usuário numa tela de erro só por causa do logout.
        }

        Cookies.remove("token")
        router.push("/login")
    }

    return (
        <button onClick={handleLogout} /* ...resto igual... */>
            <LogOut size={16} />
            Sair da conta
        </button>
    )
}

Repare que isso usa o auth:sanctum + a rota POST /api/logout que você já fez na tarefa 04 do backend — nenhuma rota nova aqui, só a chamada pelo frontend.

Parte 2 — Proteger rotas com middleware

Hoje, digitar localhost:3000/home direto na URL funciona mesmo sem estar logado — porque nenhuma página confere isso. Um middleware do Next.js roda antes de qualquer página renderizar, e pode redirecionar a requisição — é a versão do frontend pro que o middleware auth:sanctum faz no Laravel.

1

Criar o arquivo

Esse arquivo tem que ficar na raiz de frontend/ (mesmo nível de package.json), não dentro de app/:

frontend/middleware.ts
import { NextRequest, NextResponse } from "next/server"

const PUBLIC_PATHS = ["/login", "/register", "/", "/cursos", "/planos"]

export function middleware(request: NextRequest) {
    const token = request.cookies.get("token")?.value
    const { pathname } = request.nextUrl

    const isPublic = PUBLIC_PATHS.some(
        (path) => pathname === path || pathname.startsWith(path + "/")
    )

    if (!token && !isPublic) {
        return NextResponse.redirect(new URL("/login", request.url))
    }

    return NextResponse.next()
}

export const config = {
    // roda em todas as rotas, exceto arquivos estáticos do Next.js
    matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"],
}
request.cookies, não js-cookie Dentro de um middleware você não usa js-cookie nem next/headers — é uma terceira API, request.cookies, específica de middleware. Não precisa decorar todas — cada contexto do Next.js (Server Component, Client Component, middleware) tem seu próprio jeito de ler cookie, e cada tarefa deste guia te mostra qual usar onde.

Ajuste o array PUBLIC_PATHS conforme as páginas do projeto que devem continuar acessíveis sem login (a home pública, cursos, planos — o que fizer sentido pro produto).

Como testar

Apague o cookie token manualmente (DevTools → Application → Cookies → botão direito → Delete) e tente acessar localhost:3000/home direto pela URL. Deve te jogar pra /login automaticamente.
