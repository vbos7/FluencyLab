Logout e proteger rotas

Parte 1 — LogoutButton

frontend/app/_components/profile/logout-button.tsx
"use client"

import { useRouter } from "next/navigation"
import { LogOut } from "lucide-react"
import { apiClient } from "@/app/_lib/api"

export function LogoutButton() {
    const router = useRouter()

    async function handleLogout() {
        try {
            await apiClient.post("/auth/logout.php")
        } catch {
            // mesmo se falhar, continuamos o logout local
        }
        // O PHP destruiu a sessão — o browser descartará o cookie PHPSESSID
        router.push("/login")
    }

    return (
        <button onClick={handleLogout} /* ...classes... */>
            <LogOut size={16} />
            Sair da conta
        </button>
    )
}

Parte 2 — Proteger rotas com middleware.ts

Sem login, ninguém deveria acessar /home, /practice, etc. O middleware do Next.js verifica isso antes de cada página carregar:

frontend/middleware.ts
import { NextRequest, NextResponse } from "next/server"

const ROTAS_PUBLICAS = ["/login", "/register", "/", "/cursos", "/planos"]

export function middleware(request: NextRequest) {
    const sessao = request.cookies.get("PHPSESSID")?.value
    const { pathname } = request.nextUrl

    const ehPublica = ROTAS_PUBLICAS.some(
        (r) => pathname === r || pathname.startsWith(r + "/")
    )

    if (!sessao && !ehPublica) {
        return NextResponse.redirect(new URL("/login", request.url))
    }

    return NextResponse.next()
}

export const config = {
    matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"],
}
request.cookies.get("PHPSESSID") — diferente do js-cookie, aqui usamos a API nativa do Next.js para middleware, que lê os cookies diretamente da requisição HTTP, sem JavaScript do browser.

Parte 3 — Endpoint "quem sou eu?" (me.php)

O middleware acima resolve uma direção: barra quem não está logado. Falta a direção inversa — quem já está logado não deveria ver as telas de /login e /register, e sim ir direto pra /home.

Por que o middleware não resolve isso? Ele só checa se o cookie PHPSESSID existe. Mas o session_start() (dentro do cors.php) cria esse cookie pra qualquer visitante, mesmo sem login. Então "cookie existe" ≠ "está logado". Pra saber de verdade, precisamos perguntar ao PHP quem é o dono da sessão.

Criamos um endpoint que lê a sessão e responde com o usuário logado — ou 401 se não houver ninguém:

backend/api/auth/me.php
<?php
require_once __DIR__ . '/../cors.php';
require_once __DIR__ . '/../db.php';

// O cookie PHPSESSID existe pra qualquer visitante — o que importa
// é ter $_SESSION['user_id'], gravado só no login/registro.
if (!isset($_SESSION['user_id'])) {
    json_out(['error' => 'Não autenticado'], 401);
    exit;
}

// Busca os dados atuais no banco (nome/email podem ter mudado desde o login)
$stmt = $pdo->prepare("SELECT id, name, email, role FROM users WHERE id = ?");
$stmt->execute([$_SESSION['user_id']]);
$user = $stmt->fetch();

// A sessão aponta pra um usuário que não existe mais (ex: conta deletada)
if (!$user) {
    session_destroy();
    json_out(['error' => 'Não autenticado'], 401);
    exit;
}

json_out([
    'id'    => (int) $user['id'],
    'name'  => $user['name'],
    'email' => $user['email'],
    'role'  => $user['role'],
]);

Parte 4 — Redirecionar quem já está logado

Agora o frontend pergunta ao me.php no servidor, antes de renderizar a página — assim não tem "flash" da tela de login aparecendo por um instante. Adicione um helper no server-api.ts (criado na tarefa 24):

frontend/app/_lib/server-api.ts (adicionar)
export type AuthUser = {
    id: number
    name: string
    email: string
    role: "student" | "admin"
}

// Retorna o usuário logado ou null. NÃO lança erro no 401 —
// "não está logado" é uma resposta esperada, não uma falha.
export async function getCurrentUser(): Promise<AuthUser | null> {
    const cookieStore = await cookies()

    try {
        const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/auth/me.php`, {
            headers: {
                Accept: "application/json",
                Cookie: cookieStore.toString(),
            },
            cache: "no-store",
        })

        if (!res.ok) return null // 401 = não logado
        return res.json()
    } catch {
        // Backend fora do ar: trata como "não logado" em vez de quebrar a página
        return null
    }
}

Depois, transforme as páginas de login e registro em Server Components assíncronos e faça o check no topo. Note o async na função e o await:

frontend/app/(auth)/login/page.tsx
import { redirect } from "next/navigation"
import { AuthBackground } from "@/app/_components/auth/auth-background"
import { LoginForm } from "@/app/_components/auth/login-form"
import { getCurrentUser } from "@/app/_lib/server-api"

export default async function LoginPage() {
    // Já logado? Não faz sentido ver a tela de login — manda pra home.
    const user = await getCurrentUser()
    if (user) redirect("/home")

    return (
        <main /* ...classes... */>
            <AuthBackground />
            <LoginForm />
        </main>
    )
}
Faça o mesmo em frontend/app/(auth)/register/page.tsx: adicione async, chame getCurrentUser() e redirect("/home") se houver usuário.

Como testar

Direção 1 — deslogado não entra nas rotas internas: apague o cookie PHPSESSID (DevTools → Application → Cookies → botão direito → Delete) e tente acessar localhost:3000/home — deve redirecionar pro /login.

Direção 2 — logado não vê o login: faça login normalmente, depois digite localhost:3000/login na barra de endereço — deve redirecionar direto pra /home.

No terminal, dá pra conferir o me.php isolado:

# sem sessão → 401
curl -i http://localhost:8000/api/auth/me.php

# com sessão (salva o cookie no login, reusa no me)
curl -c cookies.txt -X POST http://localhost:8000/api/auth/login.php \
  -H "Content-Type: application/json" \
  -d '{"email":"ana@test.com","password":"123456"}'
curl -b cookies.txt http://localhost:8000/api/auth/me.php   # → 200 + dados
